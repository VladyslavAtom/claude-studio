A team of Claude Code agents, side by side in git worktrees

Claude Studio is a desktop app for parallel agent work. Open a repository, start a session, and let the lead agent hand parts of the task to sessions of their own: each on its own branch, each with one job, all in one window.

How it works

From one task to a team, in four steps

The app shows and connects real Claude Code sessions. The agents keep doing what they do in a terminal; the app gives them branches, a place on screen and a way to hand work to each other.

1

Open your repository

Every repository is a project tab with a colour of its own, so you always know where you are. Open a local folder or clone one by URL; a folder inside a repository binds to its root.

2

Start a session with a task

A session is a branch claude/<slug> in <repo>/.worktrees/<slug>, kept out of git status through .git/info/exclude. Claude starts in it already holding your task, in a real terminal, with your own CLI, settings and subscription.

Need the agent in the project folder itself? A session can share it instead of getting a worktree.

3

Ask the lead to split the work

Every Claude tab carries four tools. Ask for a split in plain words:

Split this into the payments API, the checkout form and e2e tests. Open a session for each, check on them, and tell me when they are ready to merge.

The lead calls open_session once per part: a visible session on a branch forked from its own, with a Claude already holding the sub-task. It checks on them with list_sessions (tab state, uncommitted files), sends follow-ups with send_to_session, and closes them with close_session.

API, UI and tests is an example: the split is whatever you ask for. Up to 3 levels deep, 8 open children per session.

4

Review, merge, close

Read each child's diff, merge its branch into the lead from the branch menu, then close it. A child whose commits are not in the lead yet is not deleted: closing refuses, or keeps its worktree and branch on disk.

The lead's branch then goes the usual way: push, a pull request through gh, or a merge into main.

Review

See exactly what each agent did

  • Side-by-side diff in the style of JetBrains IDEs: edit in place, revert one change with a click, jump between differences, fold what did not change.
  • Changes panel as a list or a tree, checkboxes per file and folder, commit with a message a model writes from the diff.
  • Three-way merge for conflicts: yours, the result and incoming, an arrow per conflict, and a result you can edit by hand.
  • Branch work without leaving the window: push, pull with a choice of strategy, rebase, merge, a pull request.
History

Every conversation, findable

  • All Claude and Codex conversations recorded for the project's folders, including ones started outside the app, from a plain terminal.
  • Full-text search inside what was said: your prompts and the agents' answers, with the matching lines highlighted.
  • Closed sessions stay in the session history and can be brought back; Open resumes any conversation in a tab.
Details

Made for long days with many agents

The small things that decide whether you can keep eight agents busy without losing track of any of them.

Statuses you can trust

Working, waiting for you, idle, asleep: Claude Code tabs report it themselves through hooks, and the output stream is only the fallback. A notification and a sound when one needs you.

Sleeping tabs

An agent idle for N minutes is stopped and keeps its conversation and its last screen. One click wakes it where it left off: memory goes to the agents that work.

A conversation per tab

Each Claude tab gets its own session id, Codex reports its thread. Two agents in one folder never resume each other, and after a restart each tab resumes its own conversation (a Codex tab once it has answered at least once).

Real terminals

xterm.js with WebGL, search, scrollback kept across switches. Paths an agent prints are links that open the file at that line.

State survives

Projects, sessions and tabs come back after a restart. The state file is written atomically, with backups, and never silently overwritten.

Dark, light, three languages

English, Українська, Русский. Theme and language follow the system until you choose. git terms are never translated.

Files and editor where the agent works

A file tree per session with the context menu you expect: new, rename, move, duplicate, copy path, open in a terminal, show the diff or the history of a file, revert it. A CodeMirror editor that saves on a pause and picks up what an agent wrote meanwhile.

Setup

Your agents, your way

  • Agents are presets: Claude, Codex, or any CLI you add. Command, arguments with {session} and {name}, environment, colour and order.
  • Several accounts: environment per preset, e.g. CLAUDE_CONFIG_DIR for a second Claude profile.
  • Sleep, notifications, commit messages, git and editor each have their own page.
FAQ

Questions

Is it free?

Yes, MIT licensed. You need your own Claude Code (or Codex) subscription or API access: the app starts the CLIs you already have, it does not bundle or resell them.

Why not tmux and git worktree?

That is the core of it, and it works. What the app adds: a worktree and a branch per session made for you, a conversation id per tab so agents never resume each other, statuses from Claude Code hooks instead of watching panes, sleeping and waking agents, diffs, commits and merges per worktree, and agents that can open visible sessions for each other.

Do child sessions work with Codex?

Codex runs fine as a tab, with its own conversation, history and search. The four session tools are given to Claude tabs only, so a split is led by Claude.

What does it send over the network?

The app itself makes no network calls: no account, no telemetry, no updater. The agents, git, gh and the generated commit message run through your own CLIs and subscriptions. Its own state is a local file, ~/.config/claude-studio/state.json.

What does it change in my repository?

Session worktrees go to <repo>/.worktrees/, which is added to .git/info/exclude, and branches are named claude/<slug>. Closing a session removes a clean worktree and a branch that has nothing outside its base; anything else is kept unless you say otherwise.

macOS? Windows?

Developed and used on Linux (Ubuntu 24.04, KDE Plasma, X11 and Wayland). The code has no Linux-only calls and the build has dmg/zip targets, but it has never been run on macOS. There is no Windows build.

Is it made by Anthropic?

No. It is an independent open-source project, not affiliated with Anthropic or OpenAI.

Install

Build from source

No release binaries yet. Five commands on Linux, plus an optional AppImage.

Linux

X11 or Wayland. Developed on Ubuntu 24.04 with KDE Plasma.

Node.js 22.5+, git

gh for pull requests.

Claude Code or Codex

On PATH and signed in. The app starts them; it does not bundle them.

git clone https://github.com/VladyslavAtom/claude-studio
cd claude-studio
npm install
npm run rebuild      # node-pty against the Electron ABI
./claude-studio.sh   # build if needed and start; --help for the rest
npm run dist         # or build an AppImage into release/

Ubuntu 24.04+ restricts unprivileged user namespaces through AppArmor, so the scripts set ELECTRON_DISABLE_SANDBOX=1.
