Команда агентів Claude Code пліч‑о‑пліч у git worktree

Claude Studio - десктопний застосунок для паралельної роботи агентів. Відкрийте репозиторій, запустіть сесію, і головний агент роздасть частини задачі окремим сесіям: кожна на своїй гілці, у кожної одна справа, усі в одному вікні.

Зібрати з коду Відкрити на GitHub

Демо-репозиторій. Головна сесія і три сесії, які вона відкрила, кожна на своїй гілці; праворуч - що змінила одна з них.

Як це працює

Від однієї задачі до команди за чотири кроки

Застосунок показує і поєднує справжні сесії Claude Code. Агенти працюють так само, як у терміналі; застосунок дає їм гілки, місце на екрані і спосіб передавати роботу одне одному.

1

Відкрийте свій репозиторій

Кожен репозиторій - вкладка проєкту з власним кольором, тож ви завжди знаєте, де ви. Відкрийте локальну теку або клонуйте за URL; тека всередині репозиторію прив'язується до його кореня.

2

Запустіть сесію із задачею

Сесія - це гілка claude/<slug> у <repo>/.worktrees/<slug>, прихована від git status через .git/info/exclude. Claude стартує в ній уже з вашою задачею, у справжньому терміналі, з вашим CLI, налаштуваннями і підпискою.

Потрібен агент у самій теці проєкту? Сесія може працювати в ній замість окремого worktree.

3

Попросіть головного агента розділити роботу

Кожна вкладка Claude має чотири інструменти. Попросіть розділити роботу звичайними словами:

Розбий це на API платежів, форму оплати та e2e-тести. Відкрий сесію для кожної частини, стеж за ними і скажи, коли вони будуть готові до merge.

Головний агент викликає open_session для кожної частини: видима сесія на гілці, відгалуженій від його власної, з Claude, який уже має підзадачу. Стан він перевіряє через list_sessions (статус вкладки, незакомічені файли), доручення надсилає через send_to_session, закриває через close_session.

API, UI і тести - лише приклад: ділиться так, як ви попросите. До 3 рівнів вкладеності, до 8 відкритих дочірніх сесій на одну.

4

Перегляньте, зробіть merge, закрийте

Перегляньте diff кожної дочірньої сесії, зробіть merge її гілки в головну з меню гілки, потім закрийте її. Дочірня сесія, чиїх комітів ще немає в головній, не видаляється: закриття відмовить або залишить її worktree і гілку на диску.

Далі гілка головної сесії йде звичним шляхом: push, PR через gh або merge у main.

Перегляд

Бачите точно, що зробив кожен агент

  • Diff пліч-о-пліч у стилі IDE JetBrains: правка на місці, відкат однієї зміни кліком, перехід між відмінностями, згортання незміненого.
  • Панель змін списком або деревом, прапорці на файли і теки, commit із повідомленням, яке модель пише за diff.
  • Трибічний merge для конфліктів: ваше, результат і вхідне, стрілка на кожен конфлікт і результат, який можна правити вручну.
  • Робота з гілками не виходячи з вікна: push, pull з вибором стратегії, rebase, merge, PR.
Історія

Кожну розмову можна знайти

  • Усі розмови Claude і Codex, записані для тек проєкту, зокрема розпочаті поза застосунком, у звичайному терміналі.
  • Повнотекстовий пошук по сказаному: ваші запити й відповіді агентів, зі збігами, підсвіченими в рядках.
  • Закриті сесії лишаються в історії сесій, і їх можна повернути; Відкрити продовжує будь-яку розмову у вкладці.
Деталі

Для довгих днів із багатьма агентами

Дрібниці, від яких залежить, чи вийде тримати вісім агентів у роботі й не загубити жодного.

Статусам можна вірити

Працює, чекає на вас, простоює, спить: вкладки Claude Code повідомляють це самі через hooks, а потік виводу - лише запасний варіант. Сповіщення і звук, коли агент вас чекає.

Сплячі вкладки

Агент, що простоює N хвилин, зупиняється і зберігає розмову та останній екран. Один клік будить його там, де він зупинився: пам'ять дістається тим агентам, що працюють.

Своя розмова в кожній вкладці

Кожна вкладка Claude отримує свій id сесії, Codex повідомляє свій thread. Два агенти в одній теці ніколи не продовжать розмову одне одного, а після перезапуску кожна вкладка продовжує свою (вкладка Codex - якщо вже відповіла хоч раз).

Справжні термінали

xterm.js з WebGL, пошук, історія прокрутки зберігається між перемиканнями. Шляхи, які друкує агент, - посилання, що відкривають файл на потрібному рядку.

Стан не губиться

Проєкти, сесії й вкладки повертаються після перезапуску. Файл стану пишеться атомарно, з резервними копіями, і ніколи не перезаписується мовчки.

Темна, світла, три мови

English, Українська, Русский. Тема й мова йдуть за системою, доки ви не оберете. Терміни git не перекладаються.

Файли й редактор там, де працює агент

Дерево файлів у кожній сесії зі звичним контекстним меню: створити, перейменувати, перемістити, дублювати, скопіювати шлях, відкрити в терміналі, показати diff чи історію файлу, відкотити його. Редактор CodeMirror зберігає на паузі й підхоплює те, що агент тим часом записав.

Налаштування

Ваші агенти, як вам зручно

  • Агенти - це пресети: Claude, Codex або будь-який доданий вами CLI. Команда, аргументи з {session} і {name}, оточення, колір і порядок.
  • Кілька акаунтів: оточення на кожен пресет, наприклад CLAUDE_CONFIG_DIR для другого профілю Claude.
  • Сон, сповіщення, повідомлення комітів, git і редактор мають кожен свою сторінку.
Питання

Часті питання

Це безкоштовно?

Так, ліцензія MIT. Потрібна власна підписка Claude Code (або Codex) чи доступ до API: застосунок запускає CLI, які у вас уже є, і не містить та не перепродає їх.

Чому не tmux і git worktree?

Це і є основа, і вона працює. Що додає застосунок: worktree і гілка для кожної сесії створюються за вас, id розмови на кожну вкладку, щоб агенти не продовжували розмови одне одного, статуси з hooks Claude Code замість стеження за панелями, присипляння і пробудження агентів, diff, commit і merge для кожного worktree, а ще агенти, що відкривають видимі сесії одне для одного.

Дочірні сесії працюють із Codex?

Codex добре працює як вкладка, зі своєю розмовою, історією і пошуком. Чотири інструменти сесій є лише у вкладок Claude, тож поділ роботи веде Claude.

Що він надсилає в мережу?

Сам застосунок нічого не надсилає: без акаунта, телеметрії й автооновлення. Агенти, git, gh і генерація повідомлення коміту працюють через ваші власні CLI та підписки. Власний стан - локальний файл ~/.config/claude-studio/state.json.

Що він змінює в моєму репозиторії?

Worktree сесій лежать у <repo>/.worktrees/, що додається до .git/info/exclude, а гілки називаються claude/<slug>. Закриття сесії видаляє чистий worktree і гілку, у якій немає нічого поза базовою; решта зберігається, якщо ви не скажете інакше.

macOS? Windows?

Розробляється і використовується на Linux (Ubuntu 24.04, KDE Plasma, X11 і Wayland). У коді немає викликів лише для Linux, і збірка має цілі dmg/zip, але на macOS його ще ніколи не запускали. Збірки для Windows немає.

Це зробила Anthropic?

Ні. Це незалежний open-source проєкт, не пов'язаний з Anthropic чи OpenAI.

У PATH і з виконаним входом. Застосунок запускає їх, але не містить.

git clone https://github.com/VladyslavAtom/claude-studio
cd claude-studio
npm install
npm run rebuild      # node-pty під ABI Electron
./claude-studio.sh   # зібрати за потреби й запустити; --help для решти
npm run dist         # або зібрати AppImage у release/

Ubuntu 24.04+ обмежує непривілейовані user namespaces через AppArmor, тому скрипти встановлюють ELECTRON_DISABLE_SANDBOX=1.
